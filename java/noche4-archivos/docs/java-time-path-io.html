java.time, Path y java.io

En Archivos.java conviven tres paquetes que resuelven cosas distintas: java.time para fechas, java.nio.file para rutas y operaciones modernas de archivo, y java.io para flujos de lectura/escritura.

Path y Files (java.nio.file)

Es la forma moderna de trabajar con archivos: no hay que abrir y cerrar un flujo a mano para operaciones simples, Files lo hace en una sola línea y lanza IOException (checked) si algo falla.

MétodoQué haceEjemplo
Path.of(ruta)Crea una ruta, relativa o absoluta, sin tocar el disco todavíaPath.of("productos.csv")
.toAbsolutePath()Convierte la ruta en absolutacsv.toAbsolutePath()
.resolve(otra)Concatena una ruta hijaPath.of("datos").resolve("productos.csv")
.getFileName()Devuelve solo el nombre del archivocsv.getFileName() → productos.csv
Files.writeString(path, texto)Escribe (o sobrescribe) un archivo de texto completoFiles.writeString(csv, contenido)
Files.readString(path)Lee el archivo entero como un solo StringFiles.readString(csv)
Files.readAllLines(path)Lee el archivo como una List<String>, una línea por elementoFiles.readAllLines(csv)
Files.exists(path)Comprueba si el archivo existeFiles.exists(csv)
Files.createDirectories(path)Crea carpetas (y las que falten en el camino)Files.createDirectories(Path.of("datos"))
Files.delete(path) / Files.copy(origen, destino)Borra o copia un archivoFiles.delete(csv)
Path csv = Path.of("productos.csv");

for (String linea : Files.readAllLines(csv)) {
    if (linea.startsWith("codigo")) {
        continue;
    }
    String[] partes = linea.split(";");
    // ...

Clases importantes de java.io

java.io es más antiguo: trabaja con flujos (streams) que hay que abrir y cerrar. Casi todos sus métodos declaran throws IOException (checked), así que se usan con try-with-resources para que el flujo se cierre solo.

ClasePara qué sirveDónde aparece en el curso
FileWriterEscribe texto en un archivo, carácter a carácternew FileWriter("kardex.txt") en Archivos.java
FileReaderLee texto de un archivo, el complemento de FileWriterSe combina normalmente con BufferedReader
BufferedWriter / BufferedReaderEnvuelven a FileWriter/FileReader y agregan un buffer: menos accesos a disco, y .readLine() para leer línea por líneaAlternativa a Files.readAllLines cuando el archivo es muy grande
FileRepresenta una ruta de forma antigua (anterior a Path); sirve para exists(), delete(), listFiles()Hoy se prefiere Path + Files para casi todo
IOExceptionLa excepción checked que casi todo método de java.io y java.nio.file puede lanzarcatch (IOException ex) en Archivos.java; ver también jerarquia-excepciones.html
PrintWriterComo FileWriter pero con println/printf, más cómodo para generar reportesÚtil para el kardex si se necesita formatear más líneas

El patrón try-with-resources: el recurso se declara entre paréntesis después de try, y Java llama a su close() automáticamente al salir del bloque, incluso si hubo una excepción.

try (FileWriter kardex = new FileWriter("kardex.txt")) {
    kardex.write(ahora.format(formato) + " salida " + despues.codigo()
            + " quedan " + despues.stock() + "\n");
    System.out.println("Kardex escrito");
} catch (IOException ex) {
    System.out.println("java.io no pudo escribir: " + ex.getMessage());
}

¿Files o java.io? Para leer/escribir un archivo completo de una vez, Files.writeString/Files.readAllLines (java.nio.file) es más corto. Para ir escribiendo línea por línea mientras el programa corre —como el kardex, que se abre y queda listo para más escrituras— se usa FileWriter con try-with-resources (java.io).

Checked en los tres paquetes: java.time casi no lanza excepciones checked (solo DateTimeParseException, que es unchecked). java.nio.file y java.io sí: casi todo lanza IOException, por eso siempre aparecen junto a un try/catch o un throws.
